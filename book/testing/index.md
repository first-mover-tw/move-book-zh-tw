# 測試 (Testing)

Move 的設計遵循[預設安全原則](./../foreword.md) - 其類型系統和內建防護機制可防止困擾其他智能合約語言的整個錯誤類別，例如重入攻擊、算術溢位和未經授權的資產存取。但語言安全並不等同於程式的正確性。類型系統可以確保你的程式碼不會違反 Move 的規則，但它無法驗證你的轉移邏輯是否向正確的收款者發送資金、你的拍賣是否在正確的時間關閉，或者你的存取控制是否符合你的預期政策。這些是你設計的特性，而不是語言的特性 - 只能透過測試來驗證。

在鏈上程式設計中，出錯的代價特別高：

- **財務風險**：資產處理程式碼中的錯誤可能導致資金永久喪失。轉移邏輯或存取控制中被忽略的單一邊界情況可能被利用，造成不可逆轉的損害。
- **不可變性**：一旦部署，智能合約程式碼並不總是能輕易修改，即使有升級的能力，之前版本的程式碼也將始終可用。部署前的徹底測試是你對抗漏洞的主要防線。
- **對抗性環境**：已發布的 Move 套件實際上是開源的 - 任何人都可以閱讀和反編譯鏈上位元組碼。這意味著惡意行為者可以詳細研究你的程式碼，尋找可利用的缺陷。你的程式碼必須處理的不僅是預期的輸入，還要應對有意破壞的嘗試。
- **可組合性風險**：Move 模組與其他鏈上程式碼互動。測試必須驗證你的程式碼不僅在隔離狀態下行為正確，還要在與其他套件組合時正確運作。

考量到這些風險，全面測試並非可選項 - 它對任何處理資產或實作業務邏輯的 Move 應用程式都是必不可少的。
